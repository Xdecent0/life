# Жизнь — приложения про быт на одном ядре

Пять PWA с одного адреса: **Кухня · Вещи · Уборка · Места · Проекты** плюс пульт. Один origin → один `localStorage` → один ключ доступа на всё. Бэкенда нет: статика на GitHub Pages, данные в приватном репо `kitchen-data`, выход наружу — заданиями для GitHub Actions.

Волт-хаб проекта: `D:\LifeOS\10 - Проекты\Активные\Жизнь\🏡 Жизнь.md` (там же журнал разработки и спека Кухни).

## Общие правила агента

- **Не удалять.** Ни файл, ни папку, ни строку истории — без явного «да» юзера. Включая то, что агент создал сам. Лишнее — предложить списком, не подчищать молча.
- **Необратимое — с показом.** `git reset --hard`, `clean -fd`, `push --force`, снос кэша: сначала показать, что именно исчезнет, потом ждать «да».
- **Число носит источник.** В интерфейсе видно, посчитано оно, проставлено руками или это оценка. Фолбек называется фолбеком.
- **Пустое честнее правдоподобного.** Нет данных — пустое состояние, не соседняя запись и не досочинённое значение. Дефолт, подставляющий чужие данные, — дефект.
- **Анти-театр.** Не изобретать фичи-декорации: экспорт «чтобы было», QR ради QR, скачиваемые квитанции, придуманные баллы и индексы. Дыру, которую нечем закрыть, называть дырой.
- **Каждое «никогда» — с гейтом.** Правило без проверки, которая краснеет, — украшение. Заводишь запрет — заводи тест.
- **Проза без слопа.** Без «фундаментальный / ключевой / переломный / это не X, это Y». Даты, единицы, имена, номера.
- **Комментарии — по-английски, одной фразой.** История решений идёт в журнал волта, а не в код.
- Секретов в репо нет и не бывает: ключ доступа живёт только в `localStorage` устройства.

## Эталон и карта артефактов

**Кухня — эталонное приложение.** У неё больше всего своего кода и она первой прошла все швы. Новое приложение делается копированием её путей, а не изобретением новых.

Полное приложение — это ровно эти файлы, и ни одного «пока без»:

| Слой | Путь у Кухни | Что это |
|---|---|---|
| Манифест | `apps/kitchen/manifest.js` | ключ, пустое состояние, пути в репо данных, коллекции и правила слияния |
| Точка входа | `apps/kitchen/app.js` + `index.html` | сборка экранов поверх `core/shell.js` |
| Экраны | `apps/kitchen/screens/*.js` | по файлу на экран |
| Доменная логика | `apps/kitchen/lib/*.js` | всё, что можно проверить без DOM |
| Оформление | `design/kitchen.css` | только своё; общее живёт в `design/app.css` |
| Воркер | `apps/kitchen/sw.js` | `life.serve({ key, shell: [...] })` — **список файлов оболочки** |
| Значки | `apps/kitchen/icons/` + `manifest.webmanifest` | установка на телефон |
| Строка в пульте | `core/registry.js` → `APPS[]` | `count`, `urgent`, `apply` — что видно о приложении без его запуска |
| Проверки | `test/domain.test.mjs` | доменная логика приложения, а не «оно рендерится» |

Добавить приложение = строка в `registry.js` плюс папка. Плагин-протокола нет и не заводить: пяти приложениям он не нужен.

## Ядро: что где и чего не дублировать

`core/` — всё, что не знает, про какое оно приложение. Прежде чем писать своё, проверь, что этого там нет:

`app.js` манифест · `state.js` состояние с исходящей очередью · `store.js` запись и честная жалоба на размер · `github.js` транспорт и протокол заданий · `sync.js` слияние запись-за-записью с надгробиями · `qr.js` свой QR-кодер · `pair.js` код подключения · `icons.js` значки · `registry.js` список приложений · `time.js` сроки · `money.js` валюты · `shell.js` маршруты и панель · `send.js` поделиться · `vault.js` markdown-таблицы волта · `log.js` кольцевой журнал · `screens/` карточка, шапка, скелет, настройки.

**«Когда снова» — одна арифметика.** Срок годности, гарантия, цикл уборки, «давно не был» — это `core/time.js` в разных словах. Второй формулы в приложении быть не должно.

**Обвязка — общий компонент с переназначениями.** Шапка это `core/screens/head.js`: экран назначает ей имя, строку смысла, действия справа и ряд управления — и не рисует свою. Вторая строка есть всегда, длинное имя укорачивается многоточием, фильтры уезжают вбок. Контент не должен прыгать между экранами: компьютер 132 + 60 = 192, телефон 112 + 60 = 172. **Проверять замером, а не глазом.**

**Дубль, который дешевле импорта, держится тестом.** Если ядру пришлось бы тянуть модуль приложения ради трёх строк — строки можно повторить, но совпадение обязано проверяться тестом. Разойдутся молча — потеряются события.

## Готчи, за которые уже платили

- **`tools/split_css.mjs` дополняет, не пересоздаёт.** Однажды он пересоздал листы приложений и стёр всё, написанное руками после первого разреза. Восстанавливали из git. Не возвращать пересоздание.
- **Новый файл приложения → в `shell` его воркера.** Иначе офлайн-кэш о нём не знает: на телефоне приложение живое, а файла нет.
- **Версия кэша `VERSION` в `core/sw.js`** поднимается, когда меняется оболочка. Не подняли — пользователь остался на старом.
- **Плюрализация по округлённому числу врёт.** «1.3 год» — с дробью в русском всегда «года», и запятая, а не точка. Тест такое пропускает, глаз на реальных данных — нет.
- **Тревога и инвентарь — разные вещи.** Про упавшую проверку уже кричит пульт; второй раз то же самое — шум. Ценность второго экрана в другом срезе, а не в повторе.
- **Скелет — только там, где правда ждём снаружи.** Где ничего не менялось местами, движение соврёт про то, что произошло.

## Готово — это когда

Фича или приложение не считаются сделанными, пока не верно всё:

1. `npm test` зелёный, и на новую доменную логику есть проверка, а не только на старую.
2. `window.impeccableScan()` чист на всех затронутых экранах, в обеих темах, на телефоне и на компьютере.
3. Новые файлы вписаны в `shell` воркера, `VERSION` поднята.
4. Приложение видно пульту: `count` и `urgent` в `registry.js` отвечают правду, в том числе когда данных нет.
5. Шапка взята из `core/screens/head.js`; замер высот совпадает с соседними экранами.
6. Ни одного числа без источника и ни одного правдоподобного значения вместо пустого.
7. Запись в журнал волта: что сделано, почему так, что при этом всплыло. Новая запись — сверху.
8. Карточка проекта обновлена, если изменился состав приложений, вехи или риски.

## Закрытие сессии

1. `npm test`.
2. Детектор по затронутым экранам.
3. Запись в журнал волта (пункт 7 выше) — это не «потом», это часть работы.
4. Коммит вместе с журналом. `push --force` запрещён.
5. Сводка юзеру: что изменилось, что проверено, что осталось.
